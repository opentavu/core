# Opportunity Close — Custom Page Dialog

Guided dialog that captures the close inputs and closes a `tavu_opportunity`.
Invoked from the ribbon by `OpenTavu.Opportunity.Form.closeAsWon` /
`closeAsLost` (in `WebResources/js/tavu_opportunity_form.js`), which opens this
page as a centered dialog via `Xrm.Navigation.navigateTo`.

Architecture: **the opportunity is the source of truth (Arch B).** This page only
writes the terminal `statecode`/`statuscode` + the close fields onto the
opportunity and saves. The server engine does the rest:

- `Pl.Opportunity.LifecycleTracker` (Pre-Op): validates inputs, forces
  `tavu_probability` to 100 (Won) / 0 (Lost), defaults the close date, and on
  reopen re-applies the stage default probability.
- `Pl.Opportunity.CloseOrchestrator` (Post-Op): creates the
  `tavu_opportunityclose` history log and, on Won, marks the customer.

## Page identity

- **Unique name:** `tavu_opportunityclosedialog_31702` (auto-generated by Power
  Apps) — matches `CLOSE_DIALOG_PAGE` in `tavu_opportunity_form.js`. If the page is
  recreated, Power Apps generates a new suffix; update that constant to match.
- The page **must be added to the OpenTavu model-driven app** (not only the
  solution) or `navigateTo` fails with a misleading "User does not have a Teams
  license" error.

## Parameter passing (important)

`Xrm.Navigation.navigateTo` opening a **custom page as a dialog** only forwards
two parameters reliably: `recordId` and `entityName`. Arbitrary custom keys (e.g.
`outcome`) are **silently dropped**. So:

- `recordId` = the opportunity GUID (kept as a valid GUID).
- The close outcome (`"won"` / `"lost"`) is carried on **`entityName`** (a
  deliberate hijack — this page is not record-bound and never needs the real table
  name). The page reads it via `Param("entityName")`.

```js
// tavu_opportunity_form.js
var pageInput = {
    pageType: "custom",
    name: "tavu_opportunityclosedialog_31702",
    recordId: oppId,
    entityName: outcome            // "won" | "lost"
};
```

## Screen OnVisible

```powerfx
Set(varOppId, Param("recordId"));
Set(varIsWon, Param("entityName") = "won");
Set(varOpp, LookUp(Opportunities, tavu_opportunityid = GUID(varOppId)));
Set(varCloseDate, Today());
Reset(txtRevenue); Reset(drpLostReason); Reset(txtNotes)
```

## Controls

| Control | Type | Visible | Notes |
|---|---|---|---|
| `txtRevenue` | Text input | `varIsWon` | Actual Revenue. Default `Text(varOpp.'Estimated Revenue')` to prefill. |
| `drpLostReason` | **Combo box** | `Not(varIsWon)` | Items: `Choices(Opportunities.'Lost Reason')`, SelectMultiple = Off. **You must add the `Value` field** (Fields → Edit → Add field → `Value`) or it shows numeric option values instead of labels. |
| `dpCloseDate` | Date picker | always | Default `varCloseDate`. |
| `txtNotes` | Text input (multiline) | always | Close Notes (optional). |
| `btnConfirm` | Button | always | See DisplayMode + OnSelect. |
| `btnCancel` | Button | always | `OnSelect: Back()` |

### btnConfirm.DisplayMode

```powerfx
If(
    varIsWon,
    If(IsBlank(txtRevenue.Text) || Value(txtRevenue.Text) <= 0,
       DisplayMode.Disabled, DisplayMode.Edit),
    If(IsBlank(drpLostReason.Selected), DisplayMode.Disabled, DisplayMode.Edit)
)
```

### btnConfirm.OnSelect

```powerfx
Patch(
    Opportunities, varOpp,
    {
        // Set BOTH statecode and statuscode. Setting Status Reason alone to a
        // terminal value while the record is Active is rejected as
        // "The requested operation is invalid".
        'Status': 'Status (Opportunities)'.Inactive,
        'Status Reason': If(varIsWon,
            'Status Reason (Opportunities)'.Won,
            'Status Reason (Opportunities)'.Lost),
        'Actual Close Date': dpCloseDate.SelectedDate,
        'Close Notes': txtNotes.Value
    },
    If(varIsWon,
        { 'Actual Revenue': Value(txtRevenue.Text) },
        // The Combo box row is { Value: <choice> }; patch the choice itself
        // (.Selected.Value), NOT the row (.Selected) and NOT a LookUp result.
        { 'Lost Reason': drpLostReason.Selected.Value }
    )
);
If(
    IsEmpty(Errors(Opportunities, varOpp)),
    Back(),
    Notify("Couldn't close the opportunity: " & First(Errors(Opportunities, varOpp)).Message,
           NotificationType.Error)
)
```

## Ribbon command registration (opportunity Main form)

| Button | Command (Run JavaScript, param PrimaryControl) | Visibility (app-scoped Power Fx) |
|---|---|---|
| Closed as Won | `OpenTavu.Opportunity.Form.closeAsWon` | `Self.Selected.Item.Status = 'Status (Opportunities)'.Active` |
| Closed as Lost | `OpenTavu.Opportunity.Form.closeAsLost` | `Self.Selected.Item.Status = 'Status (Opportunities)'.Active` |
| Reopen Opportunity | `OpenTavu.Opportunity.Form.reopen` | `Self.Selected.Item.Status = 'Status (Opportunities)'.Inactive` |

Notes:
- The "Show on condition from formula" visibility option only appears when the
  command bar is edited **inside a specific model-driven app**, not from the table's
  form editor directly.
- Reopen needs no dialog — it is fully handled in the form script.

## Gotchas learned (do not repeat)

1. **`tavu_closetype` does not exist.** Won/Lost is encoded in the close activity's
   own `statuscode` (Won `576600001`, Lost `576600002`). The opportunity's statuscode
   is Won `576600005`, Lost `576600006`, Open `576600001`.
2. **Dialogs drop custom navigateTo params** — only `recordId`/`entityName` survive.
   Outcome is carried on `entityName`.
3. **Status transition needs both** `Status` (statecode) and `Status Reason`
   (statuscode) in the same Patch.
4. **Activities can't be created directly Completed.** `CloseOrchestrator` creates
   the `tavu_opportunityclose` Open, then updates it to Completed + Won/Lost.
5. **Modern Combo box + Choice column:** add the `Value` field so it shows labels,
   and patch with `.Selected.Value` (the choice), not `.Selected` (the row).
6. **Custom page must be added to the app**, or navigateTo throws a misleading Teams
   license error.
